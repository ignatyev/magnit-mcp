# HTTP MCP Магнит

## Что поддерживается

- `magnit_search_products`, `magnit_list_categories` для режимов `delivery`, `retail`, `express`.
- `magnit_view_cart` и `magnit_add_to_cart` для express-корзины. Сводка cart сохраняет исходные quantity/increment/catalog price; название, остаток и цена добавляются только из недавнего поиска или ограниченного product-details lookup. Единицы не конвертируются.
- Ручной вход в Магнит на официальной Android вкладке Chrome. SMS и CAPTCHA обрабатывает сам пользователь на сайте; сервис не хранит их значения и не автоматизирует решение CAPTCHA.
- `magnit_status` возвращает функции, ссылку owner UI и безопасное состояние сессии. Cookie и токены никогда не возвращаются в MCP.
- `magnit_get_shopping_context` читает активные адреса без apartment/doorPhone/entrance/floor; сохранённый код магазина происходит из поиска и не привязывается к адресу.
- `magnit_get_product_details` читает конкретный товар для выбранного express-магазина; суммы/units остаются в исходных единицах.
- `magnit_apply_cart` применяет пакет `add/set/remove` одним PUT по недавним проверенным nonweighted IDs; `request_id` обеспечивает replay-safe поведение.
- `magnit_get_order_history` показывает статусы и короткий список товаров, не выводит адреса/платёжные ссылки; артикулами нельзя изменять корзину.

Оформление заказа и оплата не поддерживаются. Удаление возможно только для точных позиций текущей express-корзины через пакетный инструмент; add/set разрешены только для недавно проверенных nonweighted товаров; точное удаление позиции из текущей корзины доступно, включая пакетное удаление всех её позиций. Суммы `lite` не являются итоговым чеком. Автоматическое добавление доступно только для недавно найденного товара, соответствующего ограниченному правилу наблюдавшегося express HAR: совпадающие непустые `id`/`productId`, `service` и `targetCart` равны `express`, выбранный `storeCode`, товар не весовой, `minOrderQuantity=1`, `orderStepQuantity=1`, остальные ограничения товара равны `false`. Правило не прошло live-проверку; весовые товары исключены.

Добавление читает актуальную корзину, проверяет один express формат и контекст магазина, сохраняет все текущие `goodId`, `offerId`, `qnty`, выполняет ровно один `PUT`, затем сравнивает все позиции и количества с ответом. Счётчик `formats.itemsCount` может отставать от `items.length`, поэтому сервис не принимает его за размер корзины. Неизвестные позиции, повторы идентификаторов, другой сервис/магазин или несколько форматов блокируют запись. Неопределённый результат сохраняется в отдельном зашифрованном журнале: новые изменения блокируются до отдельного успешного вызова `magnit_view_cart`. Завершённый `request_id` хранит квитанцию 30 дней; повтор возвращает только историческую квитанцию, не утверждая, что это текущая корзина. Журнал ограничен 500 записями и не удаляет нерешённые операции. Сериализация действует внутри процесса; независимые клиенты могут изменить корзину одновременно.

## Android и Termux

Требуется Node.js 22.13+, npm и `android-tools`:

```sh
pkg update
pkg install nodejs-lts npm android-tools git
git clone https://github.com/ignatyev/magnit-mcp.git
cd magnit-mcp/bridge
cp .env.example .env
```

В `.env` задайте случайный `MCP_BEARER_TOKEN` длиной не менее 32 символов. Для loopback-режима `PHONE_ACCESS_SECRET` не нужен: владелец открывает страницу напрямую, а сервис автоматически создаёт приватный ключ `./data/owner-key` с правами только владельца. Старое значение `PHONE_ACCESS_SECRET` можно оставить — локально оно не запрашивается и продолжает расшифровывать ранее сохранённую сессию. Оставьте `PUBLIC_BASE_URL=http://127.0.0.1:8080`, `HOST=127.0.0.1`. Если подключено несколько устройств, в `ANDROID_DEVICE_SERIAL` укажите serial из `adb devices -l`.

На Android вручную включите **Параметры разработчика → Беспроводная отладка**. Пара и connect используют разные динамические адреса/порты из Android настроек:

```sh
adb pair <адрес-и-порт-pairing-из-настроек-Android>
adb connect <адрес-и-порт-connect-из-настроек-Android>
adb devices -l
npm start
```

Откройте `http://127.0.0.1:8080`, `http://localhost:8080` или `http://[::1]:8080` на порту сервиса, затем нажмите **Войти в Магнит**; отдельный пароль сервиса в локальном режиме не нужен. Node использует `adb devices -l`, создаёт только собственный `adb forward` и новую вкладку официального `https://magnit.ru/` через Chrome DevTools Protocol. Никаких `adb shell`, переключений настроек, паролей, SMS или токенов CAPTCHA сервис не отправляет. Вкладка ждёт ручный вход; открывать корзину для сохранения сессии не требуется. CDP до перехода на сайт включает наблюдение в новой `about:blank` вкладке и пассивно отслеживает только точный `GET https://magnit.ru/_auth/session`. Он читает только тело auth-ответа, сохраняет лишь признак `authorized: true`, а cookies запрашивает только для URL корзины. После подтверждения входа сессия сохраняется сразу, без чтения HTTP-корзины и без необходимости открывать её в Chrome. Выберите магазин и выполните поиск в режиме «Экспресс», чтобы создать контекст корзины. Поле `cart_http_access` остаётся `unverified`, пока явное чтение корзины не проверит его. После успеха или отмены закрываются только созданная вкладка, WebSocket и собственный ADB-forward; остальные Chrome вкладки и профиль остаются открыты. Реальный Android/Chrome здесь не запускался.

Сервис не подключается к произвольному устройству: если online устройств несколько, без `ANDROID_DEVICE_SERIAL` вход просит владельца указать serial. Если ADB/Chrome не готовы, owner UI показывает настройку. Termux процесс должен работать на том же Android устройстве; удалённый Docker helper не может управлять Chrome телефона.

Официальные справки: [Chrome remote debugging on Android](https://developer.chrome.com/docs/devtools/remote-debugging) и [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/).

## Локальный запуск и внешний MCP

```sh
npm start
```

`npm start` загружает `.env`. Откройте `http://127.0.0.1:8080`, `http://localhost:8080` или `http://[::1]:8080` на порту сервиса. Plain HTTP разрешён только loopback. Для вызова Sites/ChatGPT нужен доступный bridge HTTPS URL, настроенный внешним TLS reverse proxy или самостоятельно выбранным tunnel; автоматической публикации нет. Не выставляйте локальный owner UI публично: удалённый HTTPS режим сохраняет парольную защиту и требует `PHONE_ACCESS_SECRET` длиной не менее 32 символов. Ключ удалённого режима не создаётся автоматически. В Site runtime secrets задайте `MCP_BRIDGE_URL=https://<домен>/mcp` и `MCP_BRIDGE_TOKEN` с тем же значением, что `MCP_BEARER_TOKEN`.

Docker на Linux предназначен для HTTP MCP и не может обслуживать Android CDP-вход на телефоне. Он использует TLS reverse proxy и постоянный именованный том для зашифрованной сессии. Порт 8080 напрямую наружу не публикуется.

## HAR fallback

Импорт HAR скрыт в дополнительных настройках и не нужен для штатного входа. Обычный экспорт Chrome удаляет Cookie и будет отклонён с `sanitized_export/missing_cookie`. Импортёр допускает только exact-origin HTTPS Magnit `GET/PUT /webgate/v1/carts/lite`, выбирает последнюю express запись, требует реальный Cookie и валидный контекст, затем проверяет сессию и корзину перед сохранением. Он не принимает auth/OTP/captcha endpoints и не сохраняет исходный HAR. Не передавайте sensitive HAR в чат или репозиторий.

## Воспроизводимые проверки

```sh
node --check src/server.js
```

Для версии 0.4.0 выполнялась только синтаксическая проверка. Live upstream calls, реальный аккаунт, SMS и Android на этом окружении не проверялись.
