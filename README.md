# Магнит с телефона — HTTP MCP

Исходный код: https://github.com/ignatyev/magnit-mcp. Node.js сервис выполняет каталог и корзину по HTTP. Для ручного входа он может открыть одну новую вкладку официального Chrome на том же Android-телефоне через ADB; поиск и изменение корзины не автоматизируют браузер.

## Возможности и ограничения

- `magnit_status` — функции, состояние локально сохранённой сессии и безопасный URL страницы входа владельца.
- `magnit_search_products` и `magnit_list_categories` — каталог с явным режимом `delivery`, `retail` или `express`.
- `magnit_view_cart`, `magnit_add_to_cart` и `magnit_apply_cart` — чтение и ограниченные add/set/remove express-корзины после входа. Сводка сохраняет исходные количества и суммы, а названия, остатки и цены дополняются из недавнего поиска или ограниченного запроса сведений о товаре; единицы не конвертируются. Пакетный инструмент требует request_id и сохраняет квитанции идемпотентности.
- `magnit_get_shopping_context`, `magnit_get_product_details` и `magnit_get_order_history` — адрес аккаунта без квартиры, домофона, подъезда и этажа, подробности товара и история заказов; адрес не сопоставляется магазину, артикулы заказов не являются ID корзины.
- Оформление заказа и оплата не поддерживаются. Lite-суммы корзины не являются оценкой итогового чека.

После поиска добавление разрешается только для товаров, совпавших с зафиксированным набором полей express-каталога: отдельные `id` и `productId`, `targetCart=express`, магазин текущего запроса, не весовой товар, минимум и шаг заказа 1, остальные ограничения товара выключены. Это ограниченное правило наблюдалось в одном HAR с 35 товарами и не подтверждено live; весовые товары не добавляются. Сервер хранит eligibility для недавних поисков 10 минут и требует повторного поиска после перезапуска.

Контекст магазина задаётся отдельным express-поиском; сам вход магазин не выбирает. Добавление сначала читает корзину, сохраняет все позиции и количества, отправляет ровно один `PUT`, затем сверяет весь ответ. После неопределённого ответа повторное добавление блокируется до отдельного успешного чтения корзины. Изменения из других клиентов могут совпасть по времени; у наблюдавшегося API не было условного заголовка версии. Добавление и установка количества доступны только для проверенных nonweighted товаров; удалять можно только точные позиции текущей корзины. Оформление заказа и оплата не поддерживаются. `magnit_apply_cart` хранит request_id 30 дней в отдельном зашифрованном журнале; повтор возвращает историческую квитанцию, а неопределённая операция блокирует запись до явного чтения корзины.

Контракты каталога и корзины взяты из неофициальных исходников и пользовательского HAR. Live-доступность и вход на реальном Android здесь не проверялись. Если Магнит ответит 403, запрос завершается без повтора или обхода ограничений.

## Запуск и вход на Android

Требуются Node.js 22.13+, npm и Android `android-tools` в Termux. Установите их:

```sh
pkg update
pkg install nodejs-lts npm android-tools git
git clone https://github.com/ignatyev/magnit-mcp.git
cd magnit-mcp/bridge
cp .env.example .env
```

В `.env` оставьте loopback URL и задайте случайный `MCP_BEARER_TOKEN` длиной не менее 32 символов. `PHONE_ACCESS_SECRET` в локальном режиме не нужен: страница владельца открывается напрямую, а приватный ключ автоматически создаётся в `bridge/data/owner-key`. Если ADB показывает несколько устройств, задайте точный serial в `ANDROID_DEVICE_SERIAL` из `adb devices -l`. Не публикуйте этот файл.

Один раз вручную включите на телефоне параметры разработчика и **Беспроводную отладку**, затем создайте пару и подключение в Termux. Используйте адреса и порты, показанные Android: они динамические.

```sh
adb pair <адрес-и-порт-pairing-из-настроек-Android>
adb connect <адрес-и-порт-connect-из-настроек-Android>
adb devices -l
npm start
```

Откройте `http://127.0.0.1:8080`, `http://localhost:8080` или `http://[::1]:8080` на порту сервиса, затем нажмите **Войти в Магнит**; отдельный пароль локального сервиса не нужен. Сервис откроет новую вкладку `https://magnit.ru/`; телефон, SMS-код и CAPTCHA вводятся вручную на официальном сайте. Открывать корзину для входа не нужно. Сервис пассивно ждёт успешный официальный ответ `GET /_auth/session` с `authorized: true`, затем сохраняет только cookies для домена Магнит. HTTP-доступ к корзине отдельно не проверяется. После входа выберите магазин и выполните поиск в режиме «Экспресс», чтобы создать контекст корзины. Другие вкладки Chrome не меняются. Локальный выход удаляет сохранённую копию, но не отзывает сессию на стороне Магнит.

Возможности входа настраиваются только на Android, где работает Termux сервис и локальный ADB. Docker на Linux может обслуживать MCP, но не управляет браузером владельца на телефоне.

## Подключение Sites/ChatGPT

Локальный `127.0.0.1` доступен только телефону. Для MCP вызовов из Sites нужен отдельный HTTPS endpoint, доступный Sites. Настройте внешний HTTPS reverse proxy или контролируемый tunnel самостоятельно; сервис его не создаёт и не публикует ADB/CDP наружу. Удалённый HTTPS owner UI остаётся защищён паролем и требует `PHONE_ACCESS_SECRET` длиной не менее 32 символов; локальный ключ автоматически не используется для публичного доступа.

В runtime secrets Site задайте `MCP_BRIDGE_URL=https://<ваш-домен>/mcp` и `MCP_BRIDGE_TOKEN` с тем же значением, что `MCP_BEARER_TOKEN`. Пока bridge URL или токен не заданы, Site сообщает `setup_required`.

## Дополнительный способ импорта

Локальный HAR импортёр оставлен как резервный способ. Обычный Chrome HAR очищает Cookie, а прикреплённый в этот проект файл не содержит сессионных Cookie, поэтому он не входит в Магнит. Если импортировать новый HAR, делайте это только в своём локальном сервисе; не отправляйте файл в чат или GitHub. Сервис принимает только HTTPS запросы `GET/PUT https://magnit.ru/webgate/v1/carts/lite`, требует Cookie, выбирает express контекст, проверяет вход и сохраняет только allowlist сессионных данных в шифрованном хранилище. OTP, CAPTCHA и содержимое HAR не сохраняются.

## Проверки

Из `bridge/` выполните `npm test` и `node --check src/server.js`. Тесты используют только синтетические данные и mock HTTP; реальный аккаунт Магнит, SMS и Android устройство не задействуются.
