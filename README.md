# Магнит UTCP — полностью без MCP

В этой версии UTCP-клиент запускает локальные CLI-инструменты, а сетевые запросы поиска, корзины, истории и каталога выполняются **непосредственно внутри официального Chrome на Android** через ADB и Chrome DevTools. Node.js координирует операции, но не воспроизводит Cookie самостоятельно при покупках. MCP, VPS и удалённого моста нет. Локальный HTTP-сервис нужен для входа и управления со смартфона.

## Установка на Android в Termux

Требуются Node.js >=22.13, Python, Chrome, ADB и Git.

    pkg update
    pkg install nodejs-lts python git android-tools
    git clone https://github.com/ignatyev/magnit-mcp.git
    cd magnit-mcp
    cp .env.example .env
    npm test
    npm run check
    npm start

В Android включите Параметры разработчика -> Беспроводная отладка. Выполните adb pair и adb connect, используя показанные Android адреса и порты. Проверьте adb devices -l. Держите Chrome доступным для дальнейших покупок. Откройте на этом же телефоне http://127.0.0.1:8080 и нажмите «Синхронизировать корзину». Ввод телефона, SMS и CAPTCHA — только в официальном Chrome.

По умолчанию интерфейс работает с **«Экспрессом»** (сервис `express`). При необходимости
переключитесь на обычную доставку. Для изменения корзины выбранного сервиса сначала
синхронизируйте соответствующую официальную корзину через Chrome; в UI используйте
точный `x-store-code`, показанный после синхронизации, — он может отличаться от
`formats[].storeCode` в ответе корзины. Найдите код магазина
(4–8 цифр). Код в заголовке запроса может отличаться от кода формата в ответе Магнита.

**Корзину доставки можно изменять с дополнительными ограничениями.** Магнит может вернуть
одновременно несколько форматов (доставка, «Экспресс» и другие). Клиент показывает
только товары, явно относящиеся к выбранному сервису, и не приписывает
неизвестные позиции доставке. Изменение смешанной корзины всегда блокируется.
Итоговая сумма lite-ответа при нескольких форматах не является стоимостью доставки.

Для записи доставки необходимо предварительно синхронизировать выбранный сервис и
магазин в официальном Chrome. После этого можно искать неограниченные, не весовые
товары в режиме «Доставка», добавлять по одной штуке и удалять существующие позиции.
Каждая операция: сверка IDs с каталогом (для добавления), GET перед записью,
сохранение всех исходных позиций, ровно один PUT, проверка ответа PUT и
**повторный GET** для подтверждения результата. Журнал сохраняет защиту от
повторных запросов и блокирует новую запись при неоднозначном результате.
Текущий способ записи `dostavka` основан на формате успешного Express PUT в HAR;
**успешный PUT доставки на реальном аккаунте пока не подтверждён**.
Не повторяйте действие после ошибки до проверки официальной корзины.

### Если корзина отвечает HTTP 400 serverError

Войдите в Магнит и нажмите **«Синхронизировать корзину»** в мобильном интерфейсе.
Появится новая вкладка официального Chrome: выберите там нужный магазин, переключитесь в
**«Экспресс»** и откройте корзину **обычной доставки** (не «Экспресс»). Сервис наблюдает только за запросами созданной вкладки,
сохраняет разрешённые HTTP-заголовки и cookie в зашифрованной локальной сессии **лишь
после успешного ответа HTTP 200 от официальной корзины**. Оригинальные Cookie и
идентификаторы устройства в интерфейсе не показываются.

Когда появится «корзина синхронизирована с Chrome», вернитесь в локальный интерфейс,
убедитесь, что код магазина совпадает с выбранным на сайте, и нажмите **«Показать корзину»**.
Синхронизация подтверждает официальный магазин и сервис. Последующие запросы каталога и корзины выполняются в той же браузерной среде, а не отдельным HTTPS-клиентом Node.js. Если даже официальная корзина не
открывается, проверьте её доступность в Chrome; обход ограничений доступа не реализован.
Сохранённый вход не нужно удалять.

## Миграция сохранённой сессии

В прежней установке файлы находились в bridge/data/. До удаления старого проекта перенесите owner-key, magnit-session.enc и cart-operations.enc в новый каталог data/. Ключ шифрования должен совпасть; иначе сессия недоступна. Устаревшее PHONE_ACCESS_SECRET могло использоваться как ключ, поэтому перед миграцией проверьте, какой именно секрет использовала прежняя установка.

## UTCP агент

    python -m pip install -r requirements.txt
    export OPENAI_API_KEY="ваш-ключ"
    python agent.py "Найди продукты к завтраку и собери корзину"

ChatGPT Plus не включает OpenAI API. Агент использует Python UTCP client + utcp-cli и локальный utcp-manual.json. CLI-инструменты используют Chrome DevTools через локальное ADB-подключение, не используя локальный HTTP-сервер.

Мобильная страница также содержит текстовое поле для обращения к этому агенту (после установки Python-зависимостей и ключа).

Инструменты без модели:

    npm run tool -- status
    npm run tool -- search_products "молоко" 12345 express 10
    npm run tool -- view_cart 12345 delivery
    npm run tool -- add_to_cart "молоко" 12345 ID_ТОВАРА ID_ПРЕДЛОЖЕНИЯ 1 request-delivery-0001 delivery

Замените 12345 на код выбранного магазина. Для «Экспресса» вместо delivery укажите express.

## Ограничения

- Для add/set заново выполняется поиск в express каталоге и проверяется соответствие ID. Весовые и ограниченные товары не добавляются.
- Каждая запись требует request_id, операция защищена зашифрованным журналом и локальной межпроцессной блокировкой.
- После неопределённого исхода нельзя автоматически повторять запись; сначала перечитайте корзину. Если процесс аварийно завершился и остался data/cart.lock, убедитесь, что записывающий процесс не работает, и проверьте корзину перед удалением блокировки.
- Нельзя исключить одновременные изменения корзины официальным приложением.
- Обычная доставка поддерживается для поиска, просмотра и ограниченных изменений при проверенном браузерном контексте. Весовые/ограниченные товары автоматически не добавляются; состав после записи должен подтвердиться повторным чтением.
- Оформление и оплата не поддерживаются, суммы lite — не окончательная стоимость.
- API Магнита основаны на неофициальных наблюдениях. Реальная доступность и вход на Android здесь не проверены. Ошибки 403 не обходятся.
- Интерфейс доступен только локально на 127.0.0.1. Не публикуйте файлы .env, data/ и Cookie.
- ChatGPT в текущем чате не умеет подключать локальный UTCP-манифест; запускайте агент отдельно на своём устройстве.

## Тестирование

npm test запускает синтетические тесты модулей API, корзины и входа; npm run check проверяет Node-синтаксис. Это не заменяет проверки на устройстве.


## Основной режим: Экспресс

Откройте локальную страницу и нажмите «Синхронизировать корзину», затем в официальном
Chrome выберите «Экспресс» и откройте его корзину. Используйте код магазина из
заголовка запроса (`x-store-code`), показанный в UI; не подставляйте автоматически
`formats.storeCode`. После синхронизации выполните поиск и просмотр корзины.
Добавление/удаление защищено журналом request_id и проверяется свежим GET после
однократного PUT. Если проверка не подтвердила результат, **не повторяйте** запись,
а проверьте состав в официальном Магните. Неизвестные по сервису позиции сохраняются
в полном PUT, но удалять их из мобильного интерфейса нельзя.


### Подтверждение заголовков корзины в HAR 5 ноября 2026

Официальный Chrome для сервиса `express` с request `x-store-code: 233472`
передал GET корзины (4 строки, 1 формат) и успешный PUT (5 строк, 1 формат).
И GET, и PUT в записи **не содержат** `x-new-magnit`; UTCP теперь тоже
не отправляет этот заголовок по умолчанию. Для read-only диагностики кнопка
«Сравнить GET» по-прежнему выполняет два чтения: с прежним заголовком и
без него. В этой корзине `formats.itemsCount=2` при 5 строках ответа;
считать это число общим количеством товаров нельзя. Новое количество
признаётся подтверждённым лишь после независимого GET, а при неоднозначном
ответе запись не повторяется автоматически.


## Одна кнопка для диагностики (без изменения корзины)

В локальном интерфейсе выберите сервис (например, «Экспресс») и код магазина
из подтверждённого Chrome, затем нажмите **«Собрать диагностику»**.
Сервер собирает в одном безопасном JSON-отчёте: подтверждение браузерного
контекста, последний снимок официального Chrome на Android, количества
товаров и форматов корзины для двух вариантов GET, различия в названиях
HTTP-заголовков, количество Cookie без значений, сводку поиска молока
без названий/ID/цен, состояние журнала операций и версии среды выполнения.

Кнопка **не отправляет PUT**, не изменяет корзину и не сбрасывает журнал
неопределённых операций. Используются только GET корзины и POST поиска.
После сбора нажмите **«Скопировать отчёт»** или **«Скачать JSON»** и пришлите
полученный текст/файл. Запрещено помещать в отчёт Cookie, Authorization,
значения заголовков, ID товаров, адреса, имена или телефон. Если версия
сессии была синхронизирована до появления записи названий заголовков,
в отчёте будет `header_coverage_available: false`; один раз повторите
синхронизацию официальной корзины на Android для этой части диагностики.

### Cookie при синхронизации официальной корзины (5 ноября 2026)

Синхронизация через Android Chrome теперь при подтверждённом GET HTTP 200 по
точному адресу `https://magnit.ru/webgate/v1/carts/lite` сохраняет
**фактически отправленный браузером Cookie-заголовок** (включая порядок и
повторяющиеся имена), а не урезанный результат `Network.getCookies`.
Он хранится только в локальном зашифрованном файле сессии; в интерфейсе и
отладочном JSON публикуется лишь `cookie_source: official_cart_request` и
количество Cookie. Синхронизация без доступного заголовка сохраняет прежний
ограниченный режим `cookie_store_filtered` и требует повторной проверки
реальной корзины перед добавлением.


### Дополнительная диагностика: заголовки Chrome и протокол HTTP/2

После обновления кода **повторно синхронизируйте «Экспресс» в официальном
Chrome на Android**, чтобы локальная зашифрованная сессия сохранила разрешённые
значения `accept-language`, `sec-ch-ua*`, `sec-fetch-*` и `priority`.
Cookie и значения этих заголовков в экспортируемый JSON **не включаются**.

Кнопка «Собрать диагностику» в одном отчёте выводит
`transport_matrix` с результатами трёх дополнительных **GET без записи**:

- `node_fetch_with_browser_values`: прежний Node `fetch` с разрешёнными заголовками Chrome;
- `node_http2_baseline`: прямое чтение корзины через Node HTTP/2;
- `node_http2_with_browser_values`: HTTP/2 с разрешёнными заголовками Chrome.

Для каждой пробы показываются только количество строк, количество форматов,
состояние контекста либо короткий код ошибки. HTTP/2 подключается только к
`https://magnit.ru`, не следует редиректам и не выполняет `PUT`.
Диагностика не изменяет обычные запросы добавления, не сбрасывает журнал и
не заменяет сессию. Даже совпадение заголовков и протокола не гарантирует
одинаковое поведение: TLS, браузерное состояние и серверный маршрутизатор
могут различаться. Новые автоматические тесты в этой ветке не добавлялись.


## Использование Chrome для всех покупок

Сервис выбирает только ранее синхронизированные магазин и сервис. При каждой
операции поиска, просмотра, изменения корзины и чтения аккаунта UTCP:

1. Подключается к запущенному Chrome на Android через локальный ADB/CDP.
2. Открывает временную вкладку **именно** `https://magnit.ru/`.
3. Выполняет разрешённый запрос `fetch` в контексте этой вкладки: Chrome
   самостоятельно добавляет Cookie, User-Agent и браузерные заголовки.
4. Передаёт структурированный ответ обратно в UTCP, затем закрывает
   **только временную вкладку**, не трогая личные вкладки.
5. При добавлении выполняет строго один `PUT` и повторный `GET`; за
   журналом операции и запретом автоматических повторов следит Node.js.

Поддерживаются чтение каталога, поиск, детали товара, корзина, история заказов,
контекст магазина, добавление и удаление, если соблюдены ограничения товара и
контекста. **Оформление заказа и оплата не реализованы.**

Никакого автоматического возврата на прямой Node.js HTTPS при недоступном Chrome
нет. Если беспроводная отладка отключена или магазин не синхронизирован, сервис
сообщит об ошибке. Прежние пробы Node.js HTTP остаются **только** в диагностике
для сравнения с `chrome_runtime`. Отчёт не включает Cookie или личные данные.

Операции с реальным аккаунтом в новой Chrome-схеме ещё нужно подтвердить на
телефоне: сначала «Показать корзину», затем один безопасный добавляемый товар
и повторное чтение. После неоднозначного ответа повторно добавлять его нельзя.
Новые автоматические тесты для этого изменения не добавлялись.
